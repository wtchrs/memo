The goal of this architectural spike is to evaluate replacing our current Node.js/Express backend with Bun to reduce cold start times and improve overall throughput for the heavy I/O operations involved in our sync engine.

Initial Setup and Postgres Driver

Instead of relying on standard pg which has some overhead, Bun provides a native, highly optimized SQLite driver. However, since our core data store is Postgres, we need to evaluate postgres.js vs standard pg under Bun's runtime.

import postgres from 'postgres'

const sql = postgres({
  host: process.env.PGHOST,
  max: 10,
  idle_timeout: 20
})

export async function getUserData(userId) {
  const users = await sql`
    SELECT id, name, last_sync 
    FROM users 
    WHERE id = ${userId}
  `
  return users[0]
}

Performance Observations

  • Startup time decreased from ~450ms (Node) to ~35ms (Bun).
  • Memory footprint during high concurrency requests stayed stable around 80MB vs Node's 140MB.
  • TypeScript execution without a separate build step dramatically improved developer iteration speed.

Next steps involve load testing the specific endpoints that handle the large JSON payload transformations before we commit to a migration path.
